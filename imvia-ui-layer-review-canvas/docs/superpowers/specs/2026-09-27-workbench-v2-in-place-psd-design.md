## 1. 目标与完成定义

把“一张原图、逐项切换拆分页面”的操作改为“一张原图、同页管理全部选区和图层”。用户在原图上定义拆分区域，在右侧编辑、提交和检查结果，最终得到保持原图尺寸与位置关系的分层 PSD。

用户已明确：

- 海报与 H5 是两个上传入口，共用新版操作框架。
- 所有拆分项在同一主页面用线框和名称区分，右侧列表与画布联动。
- 列表顶部 `＋` 提供预设类别与自定义类别。
- 单项编辑、放大精修是同一文档的编辑状态，不是另一个独立项目。
- 拆分通过当前 Codex 会话中的可见任务执行。
- 拆分结果按原图坐标回到原位，最终导出一个完整的分层 PSD。
- 本版只要求像素图层，不要求 Photoshop 原生文字层、矢量层或完整可编辑特效。

完成不是“页面看起来像设计稿”或“下载按钮有响应”。必须实际走通：上传 → 多选区编辑 → 可见消息确认 → 逐项执行与回传 → 原位预览 → 用户采用 → PSD 打开验证。

## 4. 界面与交互

### 4.1 空状态与原图文档

两张上传卡片分别创建 `poster`、`h5` 类型文档。上传成功后进入同页工作台；没有原图时不显示虚假的拆分进度。

每张原图有独立文档身份、尺寸、指纹和图层集合。新增原图不能静默替换现有文档的任务来源。删除或替换有任务的原图时，先明确影响范围并取消对应未完成任务；已完成资产保留在原文档记录中，不复用于新原图。

### 4.2 多选区主页面

左侧默认完整适配原图，显示所有有效选区及名称。列表项与选区使用同一个 `layerId`：点击任一方即选中另一方；只有当前选区显示拖拽手柄，重叠区域可通过列表精确选择。选区可以重叠，不自动合并、删除或重建全图所有权。

右侧列表显示名称、类别、当前状态和编辑入口。顶部 `＋` 提供主标题、文案、角色/主体、品牌/Logo、UI 组件、装饰、光效、背景及自定义类别。新增项必须由用户定义区域，不自动创建全海报拆分清单。

类别的显示名称与处理类别分开保存：主标题/文案映射 `text`，角色映射 `subject`，品牌与 UI 映射 `brand_ui`，装饰映射 `decoration_prop`，光效映射 `effect`，背景映射 `background`。自定义名称必须选择一个已有处理类别，不能把任意文本直接发给执行适配器作为未知路由。

底部“拆分”和“下载 PSD”固定可见，列表在自己的区域滚动。布局适配 Codex 侧边面板；窄视口允许面板切换，不缩小整个页面来假装适配。

### 4.3 单项编辑

编辑图标使右侧列表切换为当前项编辑器；左侧继续显示原图，当前区域突出，其他区域弱化。编辑器包含名称/类别、要求、快捷提示、去背景开关、选区工具、补充提示以及“完成”。

“完成”验证并保存编辑草稿，回到列表，不触发 ImageGen、RMBG 或消息发送。离开未保存草稿时允许保存或放弃，不静默丢失修改。

选区或处理要求改变时产生新的 `layerRevision`。仅改显示名称或叠放顺序产生文档修订，不强制重新生成像素；像素、mask、区域、来源、去背景策略或补全要求变化，必须重新建立任务快照。

### 4.4 放大精修

放大按钮初次打开时完整适配当前选区；用户主动缩放后允许局部查看和平移。可显示选区附近原图作为定位参考，但可编辑的授权范围必须明确可见。

保留贝塞尔钢笔、锚点/控制柄、选择、删除、撤销/重做、缩放及退出。每个工具必须有实际行为；魔棒仅在已有或新增的实际选区算法可用时启用，不能用装饰图标冒充能力。

钢笔路径与矩形区域属于同一个图层。退出精修回到单项草稿；“完成”统一保存。缩放、滚动和面板切换不能改变路径的原图位置。

### 4.5 结果审核与预览

选中有结果的项时，可在同页查看透明 PNG、原位叠加和历史候选。预览默认完整适配窗口，不裁掉图片底部；棋盘格只作为界面背景，不能烘焙进 PNG 或 PSD。

用户明确“采用此版本”才更新 `acceptedVersionId`。新候选不会覆盖原来的已采用文件；尝试失败时仍可查看旧结果。修改已采用项的像素配置后，旧结果标为“对应旧配置”，不得冒充当前修订已完成；仅改显示名称或顺序不使像素结果失效。

列表顺序即最终图层叠放顺序，支持调整；顶部为前景，底部为背景。调整顺序只改变合成关系，不改变像素或触发重新生成。

## 5. 原位坐标与像素契约

### 5.1 唯一基准

原图左上角是 `(0, 0)`；原图像素宽高 `W × H` 在任务生命周期内不变。视口、参考画布、PNG 与 PSD 不得各自使用隐含的缩放规则。

矩形以 `x, y, width, height` 的整数原图像素保存；拖拽过程中可以使用小数，保存时统一量化并裁到原图边界。采用半开区间 `[x, x + width)`、`[y, y + height)`，避免边界重复取整。

路径锚点和控制柄以原图像素浮点坐标保存。复用旧归一化钢笔数据时必须显式转换，不能混用“相对整张原图”与“相对选区”的归一化值。

### 5.2 查看变换

屏幕点 = 原图点 × 查看缩放 + 查看偏移。主画布、区域放大和结果叠加使用同一变换模块；指针操作使用逆变换。调整窗口尺寸、缩放或移动查看区域仅修改视图状态。

### 5.3 处理输入与输出

每次提交冻结来源指纹、图层修订、区域、路径、提示、处理类别和去背景策略。正式处理输入是这一快照的区域及必要上下文；不得因为处理一项而分析或改写未授权的其他图层。

执行期间可以编辑下一版草稿，但不能改变正在执行的快照。旧快照回来的结果归档在原修订下，不自动绑定新区域；重新生成新修订必须另建 attempt，不能修改已发送消息的含义。

规范结果是选区尺寸的 RGBA 图像与原图 `placement`：例如选区 `(129, 1522, 1280, 1451)` 对应 `1280 × 1451` PNG，在预览及 PSD 中放在 `(129, 1522)`。不先裁成 alpha 外接框再填满选区，不通过增加 6% 边距挪动真实内容。

生成模型若需要标准参考画布，必须记录选区到该画布的显式映射和 padding，并按该映射逆变换。处理画布的额外边距不得改变原图坐标；映射不存在或结果发生不明重排时返回可解释的失败/待检查，不启用缩放居中补救。

纯提取优先保留原图可见 RGB，只修改 alpha。用户授权补全或去字修复时，仅允许在指定修复范围变化；提取与重建操作类型必须在任务快照中区分。几何检查不能证明语义或细节完全正确，最终保留人工审核。

### 5.4 补全与背景

矩形是输出边界，路径描述保留/排除区域。需要补全到框外时先扩大区域、保存新修订并重新提交，不能在 finalizer 中偷偷扩大授权范围。

背景补全是明确的拆分项。完整原图只用于参考，不能默认作为可见底层遮住拆分遗漏，也不能据此宣称得到无前景内容的干净背景。没有背景层时，导出文档的未覆盖区域保持透明，并在导出摘要中明确显示。

## 6. 数据模型与模块边界

下列名称是 V2 逻辑契约，实施计划负责把它们映射到具体文件及接口；不要求全量改名旧数据。

| 对象 | 必要字段与职责 |
| --- | --- |
| `Document` | `schemaVersion: 2`、`documentId`、`mode`、`source`（路径/尺寸/指纹/版本）、`revision`、`layerOrder`、活动图层 |
| `LayerDefinition` | 稳定 `layerId`、`layerRevision`、名称、显示类别、处理类别、像素 bounds、路径、要求、处理策略、`acceptedVersionId` |
| `Batch` | `batchId`、文档身份、冻结图层快照有序列表、批次状态；不从后续实时列表动态扩充 |
| `Attempt` | `attemptId`、`dispatchId`、授权标识、图层/来源/快照绑定、消息投递状态、执行阶段、失败原因与时间 |
| `CandidateVersion` | 独立版本 ID、attempt 绑定、PNG 路径与摘要、尺寸、alpha、placement、映射和审核信息 |
| `ExportSnapshot` | 导出 ID、原图尺寸、文档修订、有序采用版本及文件摘要、合成规则、输出文件与检查结果 |

职责分离：

- V2 页面外壳：空态、列表、编辑、精修及审核状态切换。
- 原图坐标画布：图片适配、选区命中、坐标变换及叠加，不负责网络任务。
- 文档状态模块：稳定身份、草稿、修订和历史采用版本。
- 执行适配层：把海报/H5 快照转换为各自执行契约；把结果规范化为 V2 RGBA + placement。
- 队列协调器：确认、投递、串行执行、取消和恢复，不判断图像质量。
- 合成与 PSD 服务：只消费被冻结的已采用版本，输出可复核文件，不启动生成。

界面状态、消息投递状态、执行状态、候选审核状态分开保存，不用一个 `busy` 或 `completed` 标记替代全部事实。

## 7. 提交、确认与队列

### 7.1 拆分按钮

本版默认提交当前文档全部已配置、待拆分的项；已采用且配置未变的项不重复提交。有未保存草稿或无效区域时列出具体问题，先解决或明确排除，不静默发送不完整批次。失败、已取消项需要用户主动重试，不能随下一次普通拆分自动重发。

同一图层修订已有等待确认、排队、处理中或待审核的 attempt 时，不再次加入普通拆分批次。重复点击必须命中同一个提交身份，不创建重复生成；主动“重新生成”则明确产生新候选版本。

点击后冻结批次和各项快照，直接请求 Codex 宿主的可见发送确认；不再要求用户返回旧消息卡片额外点击“发送到 Codex”。宿主确认不能由工作台伪造或绕过。

推荐传送一个有限、有序的批次信封，由当前可见 Codex 回合逐项执行；每项仍有自己的 dispatch、授权、归档及取消身份。执行器只处理批次明确列出的项，不启动隐藏任务。单项适配器完成后立即返回，由批次协调流程选择下一项；旧单项终止契约不被静默改写。

批次信封与宿主确认是新增联调范围，不假定旧桥接已支持。实现必须验证一次确认实际交付完整批次；如果宿主存在尺寸或交互限制，应在工作台内明确要求分批确认，不用“提交成功”掩盖未投递。

### 7.2 用户可见状态

| 状态 | 进入依据 | 不允许的误报 |
| --- | --- | --- |
| 待拆分 | 已保存配置、尚未提交 | 不显示生成计时 |
| 等待发送确认 | 已准备请求，宿主确认/交付尚未完成 | 不能显示正在生成 |
| 排队 | 可见消息已交付，该项尚未开始 | 不能把仅 claimed 当成已执行 |
| 处理中 | 执行器实际确认开始，带具体阶段 | 连接绿点不是开始凭据 |
| 待审核 | 有可用结果和归档，等待人工采用 | 不等于正式已完成图层 |
| 已完成 | 当前修订有用户采用版本 | 旧配置结果不能冒充当前结果 |
| 失败/已取消 | 对应精确 attempt 的终态 | 不得继续占用活动队列位置 |

UI 状态由真实事件映射；保留旧 `pending/claimed/delivered/sent/finalizing` 等投递记录，不能为了显示好看伪写 `deliveredAt` 或确认回执。

### 7.3 取消、重试与重启

每项可取消；整个批次可取消剩余项。失败项归档后可继续批次中已授权的其他项，不自动重试失败项。连接/授权丢失时暂停派发，并显示需要恢复的环节。

取消立即终止对应派发资格，释放队列；执行进程支持中止时中止，不支持时展示“已取消接收，外部处理可能仍在结束”。迟到结果只能留在原 attempt 证据中，不能覆盖当前候选、恢复任务或继续触发后续项。

“重启工作台”关闭本工作台会话的旧活动/排队任务并打开空态，保留磁盘历史成果；普通刷新只恢复文档与真实状态，不自动重发。重连不得复活已终结 dispatch。重试创建新的 attempt，保留旧报告与候选。

## 8. PSD 导出

### 8.1 导出内容

一个文档导出一个 PSD，画布像素尺寸等于原图。每个参与导出的拆分项对应独立像素图层，保留名称、透明度、位置和叠放顺序。内存中可以使用区域像素及偏移，无须把每项永久存成整幅透明大图。

导出默认包含当前列表的全部有效拆分项；只有全部具备匹配当前像素修订的已采用版本时启用。用户明确移除不需要的项后可导出剩余集合，不静默跳过失败、未审核或已过期的层。

原图作为检查参考，不默认加入可见合成。初版新建图层采用 `Normal` 合成及真实 alpha；历史任务含非 Normal 混合规则时，只有预览和 PSD 同时支持且验证一致才可导出，不能静默降级混合效果。

### 8.2 导出一致性

点击时冻结 `ExportSnapshot`，绑定文档修订、图层顺序、采用版本及文件摘要。导出过程中用户编辑不改变本次文件；界面说明文件对应哪个版本，并将已过时下载标为历史版本。

后端检查文件完整、PNG 可读、真实 alpha、尺寸、placement、来源/版本一致性后，写临时 PSD，验证成功再发布最终文件。写入失败保留旧导出，不出现零字节或半成品“成功下载”。

alpha 检查与处理策略对应：去背景前景必须有有效 mask；完整背景或明确保留背景的区域允许全不透明 RGBA，不能因没有透明像素误判失败。全透明结果必须显式提示，不能作为有效可见图层悄悄通过。

下载的是实际 PSD 文件，不是改扩展名的 ZIP，不以一张合成图代替多层。画布过大、编码器不支持或内存不足时返回明确错误，不缩小原图或静默转其他格式。编码器选择及具体尺寸/内存限制由实施计划中的兼容性验证确定，不能继承旧 PNG 尺寸上限就假定 PSD 也支持。

### 8.3 验收

重新读取导出的 PSD，核验画布尺寸、层数、名称、顺序和偏移；对确定性透明图层 fixture 比较重组结果与工作台合成。再用 Photoshop 实际打开代表性文件，确认图层可单独显示/隐藏且位置正确。若无法执行 Photoshop 验证，必须单列为未完成验收，不用其他解析器的成功冒充。

## 9. 旧数据、版本和回退

V2 使用独立 schema 版本及入口切换，不直接覆写 V1 持久化结构和旧任务记录。旧数据仍可在旧视图读取；用户明确迁入 V2 时创建新文档记录并保留来源关联。

旧候选只有来源、坐标映射与采用关系可验证时才允许作为可检查历史结果导入。曾经按 alpha 外接框缩放居中的产物不能重新标记为严格原位。无法证明对应关系的记录不阻塞旧版查看，但不能自动参与 V2 PSD。

阶段性提交均限定在 `layer-review-canvas` 仓库和新版分支；旧版基线保留。规格阶段只提交文档，不安装插件、不重启服务、不推送发布，也不提交生成资产、账号配置或其他项目文件。

## 10. 验证范围和交付顺序

按以下依赖顺序交付；这是设计分解，不替代后续带文件及执行步骤的实施计划：

1. 文档与坐标契约、V2 入口和双上传空态。
2. 统一画布、类别列表、单项草稿与放大精修。
3. 批次确认与串行执行，原位 RGBA 回传、取消、失败和历史版本。
4. 同页审核、采用结果与合成预览。
5. PSD 编码、下载、重新读取与 Photoshop 验收。

关键验收场景：

- 横图、竖长图、透明图和小图初次打开完整可见，窗口变化不移动框选坐标。
- 多个有重叠的区域可以分别选中、命名和编辑，列表与框一一对应。
- 原图/选区/放大视图往返转换无累计漂移；亚像素路径不因反复缩放被量化损坏。
- 保存编辑不提交任务；一次批次确认只创建冻结范围内的任务，无重复或隐藏执行。
- 未送达、处理中、待审核分别显示；取消和失败释放队列，刷新/重启/迟到回执不复活任务。
- 原位 fixture 的像素位置、尺寸和 alpha 精确匹配；被禁止的裁边后居中路径不能进入 V2。
- 新候选或重新编辑不覆盖已采用文件；旧修订标记准确。
- PSD 层级可重新解析，实际打开可编辑像素层；合成与工作台预览一致。
- 新版可切回旧入口，旧任务和文件仍可读。

测试优先覆盖上述数据契约、变换和状态边界；界面用真实浏览器对照四张 Figma 画板检查交互与布局。纯样式细节不堆砌只复述实现的单元测试。真实生成另行记录实际调用及结果，不伪造生产成功，不自动重复收费生成。
