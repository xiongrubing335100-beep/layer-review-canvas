# Imvia Layer 工作台生命周期设计

## 目标

让工作台快速打开、持续监听当前 Codex 会话，并在页面关闭后自动释放本地资源，同时保持已经开始的拆分任务在当前会话内继续执行。

成功标准：

- 打开工作台时优先显示页面，不等待深度诊断或会话监听完成。
- 工作台打开期间，会话监听自动启动、持续心跳并在断线后自动恢复。
- 同一时刻只有一个有效工作台管理进程和一个有效会话监听可以认领任务。
- 页面全部关闭后进入 5 分钟保温期；没有活动任务时自动关闭本地服务并释放端口。
- 页面关闭时，未开始的排队任务立即取消；已经开始的任务在当前 Codex 会话继续执行。
- 页面关闭后的执行中任务永久遗弃：不回流工作台、不在下次打开时恢复，完成或失败后清理任务文件。
- 旧锁、过期认领和异常退出不能让新任务永久停在排队或处理中。
- 页面刷新、热更新和短暂断线不等同于关闭，不得误取消或遗弃正常任务。
- 生命周期清理只作用于本次关闭所标记的任务，不影响已经正常完成的历史结果。

## 已确认的产品决策

### 当前会话优先

拆分必须由当前 Codex 会话执行，不创建其他会话，也不将任务转交给独立 Codex 任务。工作台只负责把确认后的计划发送到当前会话、展示状态并接收结果。

因此，工作台关闭后虽然可以停止回流和恢复，但不能保证 Codex 当前会话完全不产生最终回复。当前会话完成任务时仍可能出现一条最终消息；该限制不通过另开会话规避。

### 自动生命周期

工作台采用自动模式：

- 至少一个页面在线时，工作台和会话监听保持运行。
- 最后一个页面离线后，没有活动任务则开始 5 分钟保温。
- 保温期内重新打开页面时直接复用现有服务并取消退出计时。
- 有活动任务时不启动退出计时，等待任务进入终态并完成清理后再开始计时。
- 5 分钟内没有页面、活动任务或新连接时，停止工作台服务、会话桥接服务并释放端口。

### 关闭后的任务语义

页面关闭不是取消已经开始的当前会话任务。

- 尚未被当前会话中的 Codex 模型确认的任务立即取消并清理；单纯完成 `ui/message` 投递不算模型确认。
- 已被模型确认、已记录有效 `turnId` 或已经执行的任务变为不可逆的遗弃状态。
- 遗弃任务继续在当前会话执行，但工作台不再接收其进度或结果。
- 即使用户在任务完成前重新打开工作台，遗弃任务也不恢复、不展示。
- 遗弃任务无论成功或失败，都在进入终态后删除最终 PNG、中间文件、计划副本和任务目录。
- 关闭前已经完成并正常回流的任务不受影响。

## 方案选择

### 方案 A：继续使用当前启动器，只增加关闭回调

优点是改动小。缺点是浏览器关闭事件不可靠，无法处理异常退出、多标签页和僵尸进程，也无法保证旧任务不阻塞新任务。

不采用。

### 方案 B：单一生命周期管理器、页面租约与任务排空

由一个管理进程统一拥有页面服务和会话桥接服务。浏览器页面通过短租约心跳声明在线，管理器根据页面数量、活动任务和保温计时决定复用或退出。

优点是启动快、状态明确，并能覆盖正常关闭、异常关闭、多标签页和活动任务。它沿用现有的会话心跳、任务认领与租约，不需要重写拆分执行。

采用此方案。

### 方案 C：每次打开和关闭都强制重启全部相关进程

状态最简单，但每次都会冷启动，且容易误杀由 Codex 管理、可能被其他任务使用的 MCP 进程。

不采用。

## 架构

### 1. 生命周期管理器

`scripts/start-workbench.mjs` 从一次性父进程升级为工作台生命周期管理器，负责：

- 建立带版本号的单实例所有权记录。
- 启动并记录页面服务与会话桥接服务的子进程。
- 暴露轻量健康状态，供再次打开时判断是否可以直接复用。
- 接收页面在线状态和任务活动状态。
- 执行保温计时、排空和关闭。
- 只停止自己记录并拥有的子进程。

管理器不得结束 Codex 自己通过 `--stdio` 管理的 MCP 进程。工作台关闭时只注销当前工作台监听和停止自己启动的本地服务，避免影响其他 Codex 任务。

所有工作台启动路径必须进入同一个生命周期管理器。现有 `ensureWorkbenchRunning()` 不再自行创建脱离管理的 Vite 进程，而是查询或唤醒生命周期管理器；否则会出现重复服务、孤儿进程和端口所有权不一致。

会话桥接内部创建的 `codex app-server` 子进程也必须登记在当前桥接实例名下，由桥接在排空完成后关闭。生命周期管理器只结束自己启动的桥接进程，桥接也只结束自己启动的 app-server 子进程。

### 2. 页面租约

每个浏览器标签页在加载时获得一个随机 `clientId`，并定期更新页面租约。页面正常关闭时发送一次离线通知；异常关闭时由租约超时兜底。

规则：

- 页面每 10 秒续租一次，连续 45 秒没有续租才判定为离线，避免短暂卡顿触发任务遗弃。
- 任意一个租约仍有效，就认为工作台页面在线。
- 关闭一个标签页不会影响其他仍在线的标签页。
- 最后一个租约失效时触发任务关闭策略。
- 页面关闭通知只把该租约标记为“疑似离线”，不能立即取消或遗弃任务；租约连续失效 45 秒后才执行不可逆关闭策略。
- 页面刷新、路由跳转、开发热更新或浏览器短暂挂起期间，只要 45 秒内有任意工作台页面重新续租，就撤销疑似离线状态并继续正常轮询与回流。
- 只有实际工作台页面计入页面租约。Codex 消息内的 MCP 连接卡片不是工作台页面，不参与页面关闭判定，也不会因工作台关闭而被生命周期管理器误杀。

### 3. 会话监听

保留现有的版本化心跳、唯一有效监听和任务认领租约，并补充以下约束：

- 页面加载不等待监听完成，先显示工作台。
- 监听在后台自动注册，状态只显示真实的连接中、在线、忙碌或离线。
- 心跳过期后停止认领新任务，并自动尝试恢复当前会话监听。
- 旧版本监听不能认领新任务。
- 同一个任务只能被当前有效监听认领一次。
- 工作台关闭且已有任务排空时，监听可以继续完成当前任务的终态确认与清理，但不能认领新任务。

### 4. 任务关闭协调器

关闭协调器以当前计划和发送记录判断任务是否已开始：

- `awaiting_codex_message`、未生效的 `claimed`、`sending_to_codex`，以及尚未被模型确认的 `submitted_to_conversation`：视为未开始，关闭时允许取消并清理。
- `sent_to_codex`、已经记录有效 `turnId`、模型已调用前台确认工具，或已经进入 `processing`：视为已开始，关闭时标记为遗弃。
- 已完成并正常回流：保持现状。
- 已失败或已取消：执行常规清理，不进入保温阻塞。

`ui/message` 被宿主接收只代表消息已送达，不等同于 Codex 已开始执行。模型确认工具写入的持久化回执或有效 `turnId` 才是“已开始”的权威边界。若投递状态写入失败，只恢复“已送达”事实，不能据此升级为“已开始”，也不能凭 UI 文案猜测。

遗弃标记必须在页面租约连续失效 45 秒后持久化，且不可因页面重新打开而撤销。45 秒判定窗口内发生重连时，不写入遗弃标记。

## 数据流

### 打开工作台

1. 打开命令检查生命周期管理器的版本化健康状态。
2. 健康且版本匹配时直接复用，不执行完整进程扫描。
3. 不健康、版本不匹配或所有权记录失效时，只清理已确认属于旧管理器的子进程并重新启动。
4. 页面服务可访问后立即打开工作台。
5. 页面创建租约；会话监听异步注册并开始心跳。
6. 启动清理器删除上次异常退出留下的已取消任务和已经确认终态的遗弃任务。
7. 对尚未确认终态的遗弃任务，先读取执行报告并在可用时查询当前 Codex turn。终态执行报告且没有可跟踪 turn，或 turn 已终止，才允许正常清理；状态无法验证时，只有超过 24 小时且没有任何新执行标记才允许兜底清理，避免删除仍在执行的当前会话任务所需文件。

### 正常拆分

1. 工作台建立任务并进入 `awaiting_codex_message`。
2. 当前有效会话监听认领任务。
3. `ui/message` 接收成功后，任务进入当前 Codex 会话。
4. 当前会话调用指定拆分 Skill 并执行。
5. 页面仍在线时，进度和 PNG 正常回流。
6. 前台当前会话路径以终态执行报告和结果验收完成作为正常完成依据；如果任务另有可跟踪的 `turnId`，该 turn 也必须进入终态。

### 页面关闭且没有执行中任务

1. 最后一个页面租约失效。
2. 取消所有尚未被当前 Codex 模型确认的任务并清理其目录；已投递但未确认的任务由串行状态写入保证取消与模型确认只有一方成功。
3. 会话监听停止认领新任务。
4. 开始 5 分钟保温。
5. 保温期内没有新页面时，生命周期管理器停止页面服务和桥接服务并释放端口。

### 页面关闭且存在执行中任务

1. 最后一个页面租约失效。
2. 尚未开始的排队任务立即取消并清理。
3. 已开始任务写入不可逆的遗弃标记。
4. 当前 Codex 会话继续执行；桥接只保留完成收尾所需能力，不再认领新任务，也不向工作台推送进度或结果。
5. 前台当前会话路径在终态执行报告写入后删除其输出、中间文件和任务目录；如果存在可跟踪的 `turnId`，还必须等待该 turn 进入终态。仅发现 PNG 不足以触发提前清理。
6. 所有活动任务排空后开始 5 分钟保温。

### 遗弃任务执行期间重新打开

1. 新页面租约上线并取消服务退出计时。
2. 遗弃任务保持隐藏且不可恢复。
3. 如果当前 Codex 会话仍忙碌，工作台显示“当前会话忙碌”；前端不建立任务，服务端也以忙碌状态拒绝提交，避免并发竞态创建隐藏队列或任务目录。
4. 当前会话恢复可用后，用户才能提交新的拆分任务。

## 状态模型

正常任务沿用现有发送阶段：

`awaiting_codex_message → sending_to_codex → submitted_to_conversation → sent_to_codex → processing → completed`

新增终止阶段：

- `cancelled_before_confirmation`：关闭页面时尚未被当前 Codex 模型确认，包括已投递但模型尚未确认的短暂阶段。
- `abandoned_running`：已经进入当前会话，但页面关闭。
- `discarding_result`：遗弃任务进入终态，正在清理文件。
- `discarded`：清理已完成。该状态不进入工作台恢复列表，只用于幂等收尾。

任务目录删除前，在任务目录外写入一个最小的短期丢弃墓碑，只包含 `jobId`、`discardedAt`、`expiresAt` 和 `status: discarded`，不保存原图、提示词、PNG 或可恢复结果。墓碑默认保留 24 小时。

任务目录删除后：

- 任务查询接口对墓碑中的任务返回 `410 Gone` 和 `status: discarded`，前端收到后从内存与本地存储移除该任务，不显示为“失败”。
- 任何迟到的进度或完成回调都按“任务已丢弃”拒绝，且不能重新创建目录或恢复 UI 状态。
- 墓碑过期后才按普通不存在处理。墓碑只用于拒绝迟到回调和清除前端幽灵记录，不构成任务恢复能力。

## 进程关闭

### 自动关闭

满足以下全部条件并持续 5 分钟后关闭：

- 没有有效页面租约。
- 没有执行中任务。
- 没有正在进行的任务清理。

关闭顺序：

1. 停止会话监听认领。
2. 清除当前工作台监听注册和心跳。
3. 让会话桥接关闭其自身创建的 app-server 子进程。
4. 停止会话桥接子进程。
5. 停止页面服务子进程。
6. 确认 4173、4174 已释放。
7. 删除生命周期所有权记录。

### 彻底退出

“彻底退出”跳过 5 分钟保温。若有当前会话任务正在执行，则页面服务立即停止，桥接进入排空模式；任务完成并清理后桥接立即退出。它不能强制停止当前 Codex 会话任务。

## 错误处理

- 页面关闭通知丢失：由页面租约超时触发同样的关闭策略。
- 页面刷新或热更新：进入 45 秒疑似离线窗口；新租约上线后撤销关闭，不改变任务状态。
- 管理器异常退出：下次启动根据所有权记录、PID 与健康版本判断并清理残留。
- 认领租约过期：恢复为可认领状态，但已取消或已遗弃任务永远不能重新入队。
- `ui/message` 已接收但模型尚未确认：仍按可取消的“已送达”处理；只有持久化模型确认、有效 `turnId` 或执行状态才能进入不可取消阶段。
- 模型已确认但状态写入失败：以可验证的确认回执或有效 `turnId` 为准，任务按已开始处理，避免错误取消正在执行的任务。
- 遗弃任务成功写出 PNG 后清理失败：记录清理失败并在下次启动优先重试，不在工作台恢复结果。
- 遗弃任务仅写出 PNG、但尚无终态执行报告：保留任务文件。存在可跟踪 `turnId` 时还要等待 turn 终止；前台路径没有 `turnId` 时，以终态执行报告作为权威收尾信号。
- 当前会话仍在处理任务：浏览器工作台的新拆分保存为可见 FIFO 排队任务；上一项产生终态报告后，会话监听自动发送下一项。
- 端口被无关进程占用：不直接结束未知进程，返回明确的端口占用错误。

## 验证

### 启动

- 冷启动能够拉起页面与监听。
- 热启动复用相同版本的健康服务。
- 页面可用不被监听重连或深度诊断阻塞。
- 旧版本、失效 PID 和端口冲突分别得到正确处理。

### 页面租约

- 单标签页关闭后进入保温。
- 多标签页关闭其中一个不会触发遗弃。
- 浏览器崩溃后由租约超时触发关闭策略。
- 页面刷新、路由跳转和热更新在 45 秒内恢复租约时，不取消、不遗弃任务，正常进度与结果继续回流。
- 保温期内重新打开会取消退出计时。

### 任务

- 未发送任务在页面关闭后取消且不再阻塞队列。
- 已送达 `ui/message` 但模型尚未确认的任务仍可取消；模型确认或产生有效 `turnId` 后不可取消。
- 已开始任务在页面关闭后继续由当前会话执行。
- 遗弃任务不回流、不恢复，成功和失败都会清理。
- 遗弃任务期间重新打开不会显示旧任务，也不会创建隐藏队列。
- 服务端在当前会话忙碌时拒绝新建任务，拒绝路径不产生任务目录。
- 迟到回调不能重建已清理任务。
- 已清理任务查询返回 `discarded`，前端移除本地记录而不是显示失败。
- 未终止的遗弃 turn 不会被启动清理器提前删除所需计划、原图或中间文件。
- 正常完成并回流的任务不会被误删。

### 关闭

- 无任务时，最后页面关闭 5 分钟后释放 4173 和 4174。
- 有任务时，任务排空并清理后才开始保温。
- “彻底退出”能够跳过保温并正确排空活动任务。
- 工作台不会结束由 Codex 管理的其他 MCP 进程。

## 非目标

- 不创建新的 Codex 会话或后台 Codex 任务。
- 不修改拆分 Skill 的图像处理算法。
- 不保证当前 Codex 会话在遗弃任务完成后完全不产生最终回复。
- 不恢复页面关闭后被标记为遗弃的结果。
- 不通过强制结束 Codex 进程来取消已经开始的拆分。
- 不批量删除 `output/jobs`，也不清理未被本次关闭流程明确标记的正常历史任务。
