# 海报工作台定向快速模式设计

日期：2026-08-21
状态：待用户审阅，尚未进入实施

## 1. 设计结论

海报分层增加一个工作台默认的“快速定向”路径，交互结构直接复用当前 H5/UI 定向分层工作台：左侧是类别和具体拆分项目，中间是原图、框选操作和 PNG 回传三个区域，右侧是当前项目的名称、提示词、去背景、钢笔工具和拆分按钮。

快速模式不等待 Codex 对整张海报做全局分析。工作台在本地快速生成类别和框选建议，用户修正后，只针对当前选中的项目调用定向海报适配 Skill。高质量全局分析入口保留，但本设计不重做其现有 UI。

## 2. 背景与问题

当前海报管线要求先提交 Codex 全图分析，再进入计划审核和逐层候选生成。该流程适合需要完整所有权图和遮挡推理的高质量任务，但不适合生产中已经知道要拆哪些类别、希望直接框选并生成的场景。

现有快速设计稿还有三个问题：

1. 底部“本地建议 / 用户确认 / 候选审核”三块没有对应 H5 工作台中的实际操作，也没有帮助用户完成拆分，应移除。
2. 左侧把类别和图层项目混在一个列表中，用户无法快速理解层级；需要显示“类别标题 → 该类别下的具体拆分项目”。
3. 中间只有一个框选画布，没有明确区分原图基准、框选操作和生成 PNG 回传；右侧也应回到 H5 的当前项目操作面板。

## 3. 目标

- 海报上传后默认进入快速定向工作台，不创建 Codex 全局分析任务。
- 本地快速识别为类别和项目提供建议框选；建议可被用户拖动、缩放、重命名、删除或新增。
- 左侧类别和具体拆分项目保持清晰的父子层级，选中项目后中间和右侧同步更新。
- 中间固定提供三个明确区域：
  - “原图展示”：完整原图，只读，作为唯一视觉基准。
  - “框选操作区”：用户调整当前项目的区域，可使用框选和钢笔工具。
  - “PNG 回传展示区”：显示当前项目生成的候选 PNG、空状态、失败详情和审核状态。
- 右侧固定提供当前项目的名称、中文提示词、去背景开关、钢笔入口和“拆分当前项目”按钮。
- 每次只处理一个已确认项目，使用类别专属规则块和一次 ImageGen 调用；不自动重试、不自动接受、不处理其他项目。
- 快速计划仍满足 `lovart-poster-layering-v3-1` 的完整字段要求，并保留完整画布、原坐标、所有权、遮挡、repair envelope 和 locked anchors 证据。
- 高质量全局分析继续沿用现有入口和 UI，本阶段只保证入口可用，不改变其内部信息架构。

## 4. 非目标

- 不修改 `lovart-poster-layering-v3-1` 基础 Skill、layer-rules 或 prompt-templates。
- 不把快速模式变成另一套全局 Codex 分析；快速模式禁止先提交整图分析任务。
- 不在本阶段重做高质量分析页面、四块候选对照页面或其计划审核信息架构。
- 不改变 ImageGen、RMBG、候选接受、正式 `layers/` 写入和最终导出安全边界。
- 不新增 Photoshop、Bridge、WebSocket 或共享 payload 协议字段。
- 不用本地颜色阈值、轮廓、克隆或自制 alpha 代替 ImageGen/RMBG 的语义处理。

## 5. 用户流程

### 5.1 进入与本地建议

1. 用户在用途选择中选择“海报分层”，上传完整画布。
2. 工作台立即显示快速定向工作台，不创建隐藏 Codex 任务。
3. 本地识别器根据画布活动区域和已有 H5 类目分析能力，生成初始类别和项目建议。建议带有“建议框选”标记和可信度，只是可编辑草稿，不是视觉权威。
4. 用户可在左侧类别下新增、删除或选择项目；在中间框选操作区修改区域；在右侧编辑名称、提示词和处理选项。
5. 用户确认当前项目后点击“拆分当前项目”。只有当前项目被提交，其他项目保持待检查。

### 5.2 单项目定向生成

1. 工作台把当前项目的类别、框选、中文提示词、保留/移除内容、遮挡者和完成范围规范化为一份 v3.1 完整图层记录，并为当前项目生成不可变的 layer snapshot。
2. 当前项目的“拆分当前项目”按钮同时承担该项目的用户确认。根计划仍可处于 `PLAN_REVIEW`，但 targeted adapter 只接受这个已确认的 layer snapshot，不要求用户先确认其他类别的项目。
3. 工作台将该项目标记为 `GENERATION_AUTHORIZED`，向当前可见 Codex 会话发送一次前台任务；不得启动隐藏后台任务。
4. 定向适配 Skill 验证 job、snapshot plan version、layer index、candidate number 和 authorization id，只读取当前项目和完整来源图。
5. Skill 读取 v3.1 基础块并附加恰好一个类别专属处理块，完成一次 ImageGen 调用。
6. 原始 PNG 保存到 `candidates/`；无论通过还是失败，都保留候选和审核报告用于 PNG 回传展示。
7. 工作台在 PNG 回传展示区显示候选、自动质检结果和中文失败原因。只有本地审核接口可以接受候选并写入正式 `layers/`。

### 5.3 项目切换

切换左侧项目时，中间三块和右侧全部切换到该项目的状态。正在生成的项目显示忙碌状态，但不得阻塞用户查看其他已保存项目；迟到回传只能更新原项目，不能覆盖当前选中项目。

## 6. 快速模式 UI

### 6.1 左侧：类别 → 具体拆分项目

左侧沿用 H5 工作台的列表交互，不增加独立的流程卡片。

类别首版固定为：

- 主体：人物、商品、角色、核心物件
- 标题文字：主标题、副标题、日期、说明文字
- 品牌与 UI：Logo、徽章、按钮、价格、角标、图标
- 装饰与道具：花束、书本、茶杯、边框、纹理等
- 光效：光晕、粒子、发光、投影
- 背景：背景墙、桌面和证据允许的补全区域

每个类别显示项目数量和展开状态；类别下直接列出具体拆分项目。项目卡显示名称、处理类别、状态（待检查 / 已授权 / 生成中 / 待审核 / 已接受 / 已拒绝）和建议框选标记。类别本身不是可直接生成的图层，只有具体项目可以提交。

### 6.2 中间：三个并列区域

中间区域不再出现底部三步说明卡，固定为三个并列视图：

1. 原图展示
   - 显示完整来源画布和原始尺寸。
   - 只读，不允许在此视图改变像素或框选。
   - 用于与框选和 PNG 回传保持同一坐标参考。
2. 框选操作区
   - 显示同一完整画布和当前项目边界。
   - 支持拖动、缩放和重置；钢笔精修由右侧“钢笔”入口开启，开启后仍在此区域操作。
   - 显示当前项目名称、类别、坐标和可信度。
   - 框选变化使项目回到待确认状态，并使该项目的非接受候选失效。
3. PNG 回传展示区
   - 生成前显示“尚未生成候选”，说明点击右侧拆分后回传到此处。
   - 生成后显示原始全画布候选，保留绿幕/黑底；透明预览只作为本地审核派生视图。
   - 失败时显示具体中文原因，例如画布尺寸、键色、配准、文字变化或来源泄漏，而不是只显示 `GENERATION_FAILED`。
   - 通过审核但未接受时明确标记“候选，未写入正式图层”。

### 6.3 右侧：当前拆分项目操作

右侧只围绕当前选中的具体项目提供操作：

- 名称：可编辑中文项目名。
- 提示词：中文文本域，包含保留内容、移除内容、禁止新增内容和位置/轮廓约束。
- 去背景：默认开启；输出透明 PNG 的机械步骤仍由现有 RMBG 合同负责。
- 钢笔：进入当前项目的边界精修，不改变原图展示区。
- 拆分当前项目：提交一次定向候选生成；按钮文案不使用“分析整张海报”。

右侧不放高质量全局证据面板，不放计划全量编辑器，也不放与当前项目无关的 release gate 细节。项目生成后的具体质检信息进入 PNG 回传展示区。

## 7. 类别专属处理规则

新建适配器 `imvia-poster-layering-workbench-targeted-v1`，保留 v3.1 作为不可变基础合同。适配器只接收一个当前项目，并按 `processing_category` 选择一个类别处理块：

| 类别 | 处理重点 | 普通硬失败关注 |
| --- | --- | --- |
| 主体 | 保持主体轮廓、比例、颜色和原坐标；只在声明 envelope 内修复遮挡 | 整体重绘、轮廓断裂、外来内容、配准不确定 |
| 标题文字 | 原样保留字形、基线、间距和颜色；禁止生成新文字 | 文字/Logo 变化、锚点变化、来源泄漏 |
| 品牌与 UI | 独立 UI 必须独立；保持徽章、价格、按钮和角标注册位置 | UI bundling、文字变化、配准不确定 |
| 装饰与道具 | 只提取来源可见资产；支持组件和遮挡关系必须可解释 | 整体资产重绘、外来装饰、envelope 超出 |
| 光效 | 只保留来源可见光效；Screen/Add 使用 `#000000` | 未证实效果、连续性断裂、键色无效 |
| 背景 | 仅在证据和 repair envelope 允许时补全背景；不得带入前景 | 背景漂移、补全缺失、前景泄漏 |

每次调用使用 v3.1 基础块加恰好一个上述类别块；不得把多个类别拼成一个候选，也不得因为当前项目复杂而自动退回全局分析。

## 8. 计划与数据合同

快速模式生成的计划仍使用 `poster-layer-plan.json`，但增加来源与路由元数据，不减少 v3.1 字段：

```js
{
  document_mode: "poster",
  planning_mode: "targeted_fast",
  planning_origin: "workbench_local_suggestion",
  display_language: "zh-CN",
  skill_contract: {
    base: "lovart-poster-layering-v3-1",
    adapter: "imvia-poster-layering-workbench-targeted-v1",
    auto_retry: false,
    full_canvas: true
  },
  layers: [{
    processing_category: "subject",
    planning_confidence: 0.86,
    user_confirmed: false,
    source_evidence: [],
    occludes: [],
    occluded_by: [],
    repair_envelope: {},
    locked_visible_anchors: []
  }]
}
```

实现时需要保持与现有计划版本兼容：原有高质量计划继续使用现有 adapter 标识；快速计划通过明确的 `planning_mode` 和 targeted adapter 路由，不得让高质量任务误走快速流程。两种计划都必须通过同一 v3.1 字段验证器，机器枚举可保留英文，用户显示层统一翻译为中文。

快速本地建议只能填写可推导字段；无法证明的来源证据、遮挡者、repair envelope 和 locked anchors 必须显示为待用户确认，不能伪造为高置信 Codex 证据。用户确认后才允许将这些字段送入生成授权。

## 9. 状态与错误处理

快速根计划状态和单项目状态分开：根计划记录所有类别和项目，单项目记录当前项目是否已经被用户确认。这样用户可以先生成一个项目，不必等待整张海报的所有项目都确认。

快速根计划状态：

```text
LOCAL_SUGGESTING → PLAN_REVIEW → PLAN_CONFIRMED
                         └──────→ PLAN_REVIEW（用户修改后）
```

根计划只有在用户明确完成快速规划时才进入 `PLAN_CONFIRMED`。在此之前，已确认的单项目仍可通过不可变 layer snapshot 进入 targeted 生成；这是新 targeted adapter 的有界路由规则，不改变 v3.1 基础规则或高质量计划的确认要求。

单项目状态：

```text
SUGGESTED → USER_CONFIRMED → GENERATION_AUTHORIZED → GENERATING → CANDIDATE_CREATED
                                                               ├→ HARD_REJECTED
                                                               └→ NEEDS_USER_REVIEW
```

`USER_CONFIRMED` 时生成的 layer snapshot 绑定当前根计划版本、框选、提示词和证据。修改该项目或根计划后，旧 snapshot 和未接受候选立即失效；其他项目的修改不应覆盖当前项目的回传状态。

失败候选必须保留在 `candidates/` 和任务诊断中；`IMAGEGEN_NO_PNG` 只在确实没有可用 PNG 时使用。已有 PNG 但尺寸、键色或注册失败，应使用对应 v3.1 失败码，并在 PNG 回传区展示事实值、要求值和下一步建议。

## 10. 高质量模式边界

本阶段不重新设计高质量 UI，也不改变其全局 Codex 分析合同。高质量入口只需要：

- 保持可访问。
- 明确标注为“高质量分析”。
- 不与快速定向项目列表混用。
- 输出文本新增中文显示约束；机器枚举和失败码仍可保留英文技术值。

高质量审核页面的四块候选对照、完整证据面板和信息层级另立后续设计任务，不在快速模式实施中顺手改造。

## 11. 实施边界与建议文件

预计实施集中在工作台和插件适配层：

- `src/main.jsx`：海报模式入口、快速计划生命周期、当前项目选择和回传状态。
- `src/fast-category-analysis.js`：复用并扩展本地类别建议，不调用 Codex。
- `src/poster-plan.js`：增加快速计划元数据、类别和来源验证，保留 v3.1 全字段校验。
- `src/PosterModePicker.jsx`：明确快速定向为默认、高质量为独立入口。
- 新建 `src/poster-targeted-plan.js` 或等价模块：把 H5 式项目数据转换为 v3.1 图层字段。
- 新建/调整 `src/PosterTargetedWorkbench.jsx`：实现左侧父子列表、中间三视图和右侧当前项目面板。
- `src/PosterCandidateReview.jsx`：将候选、失败事实和审核状态嵌入 PNG 回传区；高质量旧页面保持兼容。
- `poster-workbench-host.js`、`poster-job-store.js` 及对应服务端路由：接受 targeted_fast 来源、逐项目授权和候选保留。
- `plugin-template/imvia-layer/skills/imvia-poster-layering-workbench-targeted-v1/`：新增定向适配器、类别块和中文显示契约。

不得修改 `lovart-poster-layering-v3-1` 基础文件，也不得触及 Bridge/shared protocol、Photoshop import 或其他 RC protected runtime。

## 12. 测试与验收

### 单元与合同测试

- 本地识别在无 Codex 请求的情况下生成六类建议和可编辑边界。
- 类别标题下的具体项目可新增、删除、排序、选择，且只提交当前项目。
- 快速计划始终包含 v3.1 必需字段；缺少用户确认的证据不得被标记为 confirmed。
- targeted adapter 拒绝缺失 `processing_category`、错误 `layer_index`、错误 `plan_version`、错误 authorization 或其他项目引用。
- 每次任务最多一次 ImageGen 调用；无自动重试和自动接受。
- 普通项目使用 `#00FF00`，Screen/Add 光效使用 `#000000`；候选保持完整原画布和原坐标。
- PNG 存在但 release gate 失败时保留候选并使用正确失败码；无 PNG 时才使用 `IMAGEGEN_NO_PNG`。

### UI 验收

- 左侧可清晰区分类别标题和具体项目；选中项目后中间三视图和右侧面板同步。
- 原图展示只读；框选区可拖动、缩放、重置并显示坐标；PNG 区有生成前、生成后、失败后三种状态。
- 右侧只出现名称、提示词、去背景、钢笔和拆分操作，不出现无对应动作的底部流程卡。
- 高质量入口仍可进入现有页面，快速模式不会改变其状态。
- 中文标签、状态和失败提示可读；英文枚举仅在技术详情中展示。
- 手动检查窄屏下三视图按顺序堆叠，原图和 PNG 不被裁切到无法识别。

### 回归与安全

- 运行现有 `npm test`，并补充 targeted plan、candidate routing、failure retention 和 UI state 测试。
- 检查 diff 不触及 Bridge/shared protocol、Photoshop import、capture 或 success/reset protected functions。
- 以一张真实海报完成快速建议、用户修正、单项目候选、失败保留、接受和正式层写入的完整回归。

## 13. 验收标准

用户可以在不等待 Codex 全局分析的情况下完成：上传海报 → 选择左侧具体项目 → 中间框选 → 右侧填写提示词并点击拆分 → 中间 PNG 区查看结果。任何一次生成都只处理当前项目，候选失败可解释且可回看，高质量入口保持可用但不被快速模式的 UI 或计划污染。
