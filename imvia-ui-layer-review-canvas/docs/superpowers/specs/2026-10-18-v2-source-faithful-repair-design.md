# V2 通用原图保真修复设计

日期：2026-10-18。状态：待用户审阅；不是实现完成或效果通过报告。

## 1. 目标与边界

修复 V2 的通用拆分处理链路，而不是单独修好“歌王大赛”。原图决定文字、
Logo、主体构成、材质、比例与位置；允许模型修复缺边、细线断裂、错误孔洞
和损坏的局部，但不能把重设计当作修复。用户正常操作仍是提交拆分、接收结果、
下载文件，不承担内部边缘鉴定或模型调用确认。

保留现有文档、选区、图层顺序、编辑器、会话桥、版本历史与导出入口。
不修改已冻结任务的策略、预算、原始文件和历史检查结果。不以提高通过率为由
放宽原有提取检查，也不把旧缺陷图的哈希作为正确视觉基准。

## 2. 当前证据与路线选择

- `src/v2/execution-adapter.js` 的 `routeFor`：文字/UI 提取固定走黑白蒙版；
  reconstruct 开启去背景时固定选择 BRIA。
- `scripts/v2-region-pixels.py`：extract 的 RGB 来自原图，但错误 alpha 仍能删除
  正确包边；reconstruct 去背景时读取另一份 matte，未提供独立的原生 RGBA 通路。
- `src/v2/processing-policy.js`：现有策略为 v7，绑定处理器及契约摘要。
- 2026-10-16 两个结果的导出技术检查成立，视觉交付结论已撤回。

三种方案：继续修整黑白蒙版可保留像素，但不能作为复杂主体唯一策略；全区域
自由重绘较容易取得整洁外观，但文字、造型和位置可能改变；采用受约束的原图
修复，分离严格提取与允许修复的任务契约，是本设计推荐方案。

## 3. 新任务的明确策略

保留现有 `operation` 语义；新增版本化 `fidelityPolicy`，纳入 snapshot 摘要，
不能由执行器在模型调用后临时选择。

- `strict_source`：明确要求像素不变的任务。维持提取能力，不允许生成 RGB 替代。
- `source_faithful_repair`：允许按原图修复的任务。文字内容、Logo 身份、主体清单、
  布局、原画布位置为不可变要求；可修复轮廓及允许区域中的材质。
- 明确要求重建背景的任务继续使用重建语义，不误套透明前景提取标准。

新建图层拟默认使用 `source_faithful_repair`，但用户明确提出严格原像素要求时
必须选择 strict_source。现有文档缺失该字段时按旧语义读取，不静默迁移；
旧文档采用新策略必须产生可见的策略变更和新的图层修订。不得以无法识别自然
语言要求为由忽略冲突；执行前检查策略与处理要求的一致性。

冻结输入包括原图指纹、区域坐标、原始要求、路径、排除区域、内容清单、
保真策略、模型预算和处理器版本。执行检查生成可复用的内部数据，不含样本名、
图片哈希或针对某张图硬编码的轮廓坐标。

## 4. 模型输入与像素合成

统一使用任务准备器生成的原图参考画布，记录 contentRegion、sourceRegion、
sourcePlacement 与采样方式。提示词根据冻结内容清单和要求生成，不用历史失败
成品代替原图作为唯一依据。

新增输出类型 `native_rgba`，明确表示模型同时提供前景颜色与 alpha。
请求真透明 PNG；若模型实际返回不透明底图或棋盘格图案，不能伪装成透明成功。
不得默认调用第二次去背景、旧蒙版裁切或全局形态学修补。其他 provider 的 alpha
保留在各自明确声明的旧路线中，不能混用。

模型输出不是逐像素保真承诺。需要保留原始像素的确定区域，采用程序合成约束：

1. 原图中经检查确认且与结果对齐的正常前景，原坐标 RGB 可以保留。
2. 有证据定位的缺陷区域及边缘过渡带，允许使用模型颜色和透明度。
3. 无法可靠区分正常区域与缺陷区域时，不声称局部像素保留已经成立。
4. 源图 RGB 的保留不能覆盖模型已经正确去掉的背景，也不能用旧提取 alpha
   限制新结果。alpha 的主体完整性需独立验证。
5. 用户排除区域和修复路径是硬边界；修改不允许范围的结果不能发布。
6. 合成后的最终图必须再次检查接缝、轮廓和文字，不能只检查模型中间输出。

## 5. 坐标与文件契约

只通过准备器记录的映射还原到选区大小，再以冻结的 x/y 放回原画布。
采用预乘透明度的覆盖采样，避免透明边缘混入无效 RGB。模型输出的尺寸或内容
布局不符合映射时不猜测裁切，不按前景包围盒重新居中，不以非刚性变形伪装对齐。
位置与比例检查同时检查图像内部主体，不能只检查 PNG 宽高和图层 x/y。

预览、PNG 与 PSD 使用同一个已校验的 region RGBA。PSD 只负责编码和放置，
不再生成 alpha。保留原画布尺寸、图层名称、图层顺序和已验证位置。

## 6. 质量检查不再等同于边界分数

分别记录技术检查、内容检查、形状检查与交付检查，任何一个缺失不得由其他
检查代替。检查执行者是系统/执行 agent，不是用户勾选确认。

- 技术：文件可解码、真实透明度、映射和任务绑定、保护区不变。
- 内容：逐项检查文字/数字/Logo 和主体清单，防漏件、改字、增加装饰。
- 形状：对照原图检查整圈外轮廓、边缘厚度、细线连续性、真实孔洞、凹陷、
  边缘残色和缺失包边；暗色材质不等于孔洞。真实遮挡不应被“修复”为乱接线。
- 交付：最终图黑/白/棋盘背景与原图对照，原尺寸和放大细节均需检查；
  实际下载 PNG/PSD 并重新读取，核对 RGBA、位置及预览一致性。

报告必须带原图、输出哈希和实际检查区域证据。少数内部点、连通域数量、
全局分数或“与上一版完全相同”都不是完整轮廓验收。生成与检查职责分离，
不把生成提示词的要求直接抄成检查通过结论。自动检查能力不足时如实记录，
不通过修改状态文案掩盖；识别器是否足够可靠由留出集验证。

## 7. 修复预算、取消与重试边界

现行 AGENTS 与冻结契约禁止自动重试，旧任务继续遵守。第一阶段模型预算
仍为一次，先建立原生 RGBA、保护区合成和完整质量检查，不能偷偷多调用模型。

后续自动修复为本设计提出的独立策略变更：新提交任务可预先冻结总预算为
最多两次（初始生成一次、根据具体缺陷修复一次）。必须获得对该预算及执行
规则变更的明确认可，并同步更新项目规则/Skill，才可启用；本设计本身不
授权重试旧任务。网络中断或结果不明不自动再调用，以免重复消耗。

每次输出单独记录原图绑定、父输出哈希、模型调用和缺陷区域；模型修复不能
更改任务范围。取消立即停止后续调用；耗尽预算仍未通过时记录失败，不无限
循环、不发布劣质文件、不要求用户对错误边缘背书。保留先前合格版本，不让
新失败覆盖它。自动选用、预览和导出依据同一个最终可交付判定。

## 8. 接入范围与兼容

改动集中在 document/snapshot 策略、execution-adapter、region renderer、
processing-policy、candidate/composition/export 判定，以及 V2 批次 Skill
和 item contract。新增策略使用新版本和完整处理摘要，绑定任务路由与合成代码，
不只绑定 Python 文件。旧数据仍可读取，新旧质量报告不能互相冒充。

不在正式文档上做诊断试验，不自动替换历史候选。不更换整个前端或会话协议。
先在隔离任务存储中完成真实调用和导出，再启用新建任务默认策略。

## 9. 跨素材发布验收

基准覆盖：立体组合标题、普通文字、Logo、圆角 UI、细线装饰、真实镂空、
低对比金属与背景、不同尺寸/位置。每类至少两个不同来源素材，其中一个
留作未参与调参的验证样本；来源和使用许可随清单记录。

先固定文字清单、预期主体、可见细线/孔洞、保护区及关键轮廓的参照，再运行
新处理链路。不能从输出反推预期答案，也不能只测裁切后的局部美观截图。
对不可客观确定的原图细节记录不确定性，不编造真实 alpha。

发布至少需要：独立坐标/预乘 alpha/合成测试，错字/移位/缺件/假透明/越界修改
的负例检查，真实多素材初次调用的通过率记录，以及全套 PNG/PSD 导出回读。
对所列发布样本必须逐项合格；不能反复生成只报告最好的一次。未通过样本
暴露的共性问题必须修正或明确限制支持范围，不能宣称任意图片必然成功。

“歌王大赛”和原 UI 保留为缺陷回归样本，但不接受仅修好它们作为发布判据。
