这是一个本地运行的“无限画布 UI 拆图工作台”。用户先在工作台里框选并描述需要拆分的内容，再把单个拆分项或一批拆分项发送到当前 Codex 会话，由拆图 skill 执行抠图、补洞和 PNG 输出。处理结果需要回到工作台中展示、预览和下载。

## 2. 最终产品目标

工作台不是自动分析整张 UI 并擅自生成全部图层，而是一个“人工定义拆分计划，Codex 精确执行”的界面。

核心流程：

1. 上传原图。
2. 用户创建拆分项并选择分类。
3. 用户在原图或右侧大预览中框选目标区域。
4. 用户填写每项的具体拆分要求。
5. 用户可添加保留区域、排除区域或手绘边界。
6. 用户单独发送当前项，或批量发送确认项。
7. 当前 Codex 会话读取工作台计划和拆图 skill，执行拆分。
8. 工作台同步显示处理中状态、经过时间和最终 PNG。
9. 结果同时出现在当前项下方和无限画布的结果节点中，可预览和单独下载。

## 3. 拆分契约

### 3.1 工作台计划是唯一图层清单

- 只产出用户明确创建并发送的拆分项。
- 不允许 skill 自动增加额外图层。
- 每个确认项只对应一个最终 PNG。
- 未选择普通文字时，不生成普通文字层。
- 未选择 KV 背景时，不生成背景层。
- 不额外发布联系表、预览图、推测出的装饰层或重复图层。

### 3.2 图层分类

固定分类：

- KV-标题
- KV-元素
- KV-背景
- 普通文字
- UI 组件

UI 组件允许用户继续添加、删除和重命名。不同图片的拆分方案可以完全不同，不应让 skill 先做一次全量诊断。

### 3.3 像素与修复原则

- 可见部分优先保留原图像素，保留字体、描边、材质、压缩质感和发光效果。
- ImageGen 只用于补全被遮挡部分、文字移除后的底板空洞，以及完整背景的缺失区域。
- 不应让 ImageGen 重绘整个现有组件，否则会出现 AI 纹理、凹凸和字体变化。
- 普通 UI 文字一般合并为一个透明图层，以减少图层数量和处理时间。
- 艺术主标题、Logo 等保持独立复合层。
- UI 底板中的普通文字、可替换图标或内容应被移除，并把挖空处修复干净。
- 用户明确要求独立拆出的图标、人物、徽章或礼物图案，不应重新合回底板。

### 3.4 标注优先级

处理顺序：

```text
默认目标识别
→ 保留区域强制加入
→ 手绘边界修正轮廓
→ 排除区域强制移除
→ 去除背景并输出真实透明 PNG
```

“去除背景”不和保留、排除、手绘边界冲突。前面三类标注决定主体 mask，去除背景决定 mask 外是否透明。

### 3.5 尺寸规则

- 工作台预览可以缩放适配，但不得拉伸变形。
- 下载文件保持真实像素尺寸。
- 当前产品约定：最终 PNG 尺寸等于提交拆分时的框选尺寸。
- 拆分任务提交后，之后再调整框选区域，不应改变已经完成结果的尺寸或位置。
- 透明结果必须使用真实 RGBA，不使用棋盘格烘焙、白底或绿幕。

## 4. 当前界面结构

### 框选拆分

- 左侧：原图和拆分项列表。
- 中间上方：原图位置小预览和当前框选大预览。
- 中间下方：Codex 拆分结果区域。
- 右侧：当前拆分项编辑器。

左侧缩略图必须展示“原图当前框选区域”，不能用已经拆好的结果替代。拆分结果只出现在结果区域和结果节点中。

### 画布总览

- 原图节点。
- 用户拆分项节点。
- Codex 结果节点。
- 节点连线使用贝塞尔曲线。
- 选中节点的关联连线应有流动效果。
- 节点可选中、可拖拽。
- 点击已完成结果节点，使用站内大图弹窗查看，不打开原始 PNG 新网页。
- 已完成结果项为只读状态，不再显示“进入框选拆分”按钮。

## 6. 当前 Codex 桥接

前端提交：

```text
POST /api/layer-review/submit
```

状态查询：

```text
GET /api/layer-review/jobs/:jobId
```

结果文件：

```text
GET /api/layer-review/jobs/:jobId/files/:filename
```

任务目录：

```text
output/jobs/<jobId>/
├─ layer-review-plan.json
├─ source.*
└─ final/
```

`vite.config.js` 提供本地 API 中间件，`codex-thread-bridge.mjs` 负责启动 Codex app-server，并把计划发送给当前 Codex 会话。

默认执行 skill：

```text
split-ui-design-layers-workbench-targeted
```

关键限制：

- 必须从当前 Codex 任务启动本地服务，使进程带有 `CODEX_THREAD_ID`。
- 缺少 `CODEX_THREAD_ID` 时，工作台无法把任务发回当前会话。
- 重新启动后，应先用一个小拆分项验证当前会话桥接，而不是直接批量发送。

## 8. 已知问题与下一步优先级

### P0：真实任务链路

1. 重启本地服务后，验证 `CODEX_THREAD_ID` 和当前会话桥接。
2. 用真实拆分项测试：提交、计时、会话中处理、结果写入、前端轮询更新。
3. 确认单项提交只生成当前项，不自动扩充图层。
4. 确认批量提交只生成已确认项。

### P1：状态与尺寸

1. 结果尺寸必须固定为“提交时”的框选尺寸。
2. 提交后继续修改框选，旧结果预览和下载尺寸不能联动变化。
3. 结果节点必须使用真实输出图，侧栏和框选预览必须继续使用原图裁切。
4. 测试竖长图、横长图、小图和透明图，所有预览都不能变形。

### P1：画布交互

1. 检查所有节点的命中区域，确保容易选中和拖拽。
2. 检查已完成结果节点不显示编辑入口。
3. 检查弹窗关闭、Escape、遮罩点击等行为。
4. 检查折叠动画过程中画布与节点坐标是否抖动。

### P2：视觉整理

当前只是部分接近 LibTV，还可继续统一：

- 工具栏密度。
- 面板层级和边框对比。
- 节点标题栏、状态标记和结果节点样式。
- 更清晰的选中态和悬停态。
- 侧栏表单间距。
- 减少不必要的说明文字。

不要把界面改成营销页或卡片堆叠。它应保持专业、紧凑、适合重复操作的工具感。

### P2：命名

“重置栏目”当前含义是：

> 把拆分分类和拆分项恢复为默认方案，不替换或删除原图。

建议改名为：

```text
恢复默认栏目
```

避免用户误以为它会清空整个项目。

## 9. 不要回退的规则

- 不要让左侧缩略图显示最终结果。
- 不要让当前框选预览显示最终结果。
- 不要拉伸任何预览图。
- 不要点击结果节点后打开浏览器原始图片页。
- 不要在已完成结果检查器中显示“进入框选拆分”。
- 不要让收起后的侧栏继续占据画布宽度。
- 不要自动生成用户没选择的图层。
- 不要让 ImageGen 重绘全部可见组件。
- 不要使用绿幕作为最终输出。
- 不要在一个结果里混用真实透明、棋盘格、白底和绿幕。
- 不要因为局部失败自动重复大量 ImageGen 调用。
- 不要改变用户已经满意的结果区域高度和整体一屏布局，除非有明确新反馈。
