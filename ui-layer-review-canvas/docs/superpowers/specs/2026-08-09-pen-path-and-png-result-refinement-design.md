# 钢笔路径标注与 PNG 二次编辑设计

## 背景

工作台当前在框选精修和 PNG 结果编辑中使用连续自由画笔。自由画笔容易产生短笔、断笔和宽度不稳定的轨迹，也不适合精确描述圆角组件、人物轮廓和复杂 UI 边界。

PNG 二次编辑目前还存在三个相互关联的问题：新任务创建后会立即遮蔽上一个成功 PNG；二次编辑区没有独立的文字要求输入；提交计划缺少受支持的结果精修执行路线，并混用了 PNG 实际像素尺寸与无限画布逻辑尺寸。

本次改动把两套画笔统一替换为完整的贝塞尔钢笔，并完成 PNG 二次编辑从界面、任务协议到结果版本切换的闭环。

## 目标

- 框选精修和 PNG 二次编辑共用一套完整贝塞尔钢笔交互。
- 所有有效标注都是闭合路径，闭合后显示虚线边界和半透明语义填充。
- 消除短笔、断笔和笔刷宽度导致的标注歧义。
- PNG 二次编辑始终以最近一次成功透明 PNG 为输入原图。
- 二次编辑支持独立文字要求，并允许文字或路径任意一种触发提交。
- 排队、执行失败和重试期间保留上一版成功 PNG；只有新版本成功后才切换。
- 正确区分 PNG 实际像素尺寸和无限画布中的逻辑尺寸与位置。

## 非目标

- 不替换框选矩形、画布平移、缩放或节点选择工具。
- 不引入 Fabric.js、Konva 或其他完整画布框架。
- 不实现 Photoshop 的全部路径面板、路径布尔运算和复合形状模式。
- 不改变现有保留、排除、边界三种标注语义的优先级。
- 不在本次改动中重构与标注及结果版本无关的工作台界面。

## 方案选择

### 采用：原生 SVG 贝塞尔编辑器与统一路径模型

在现有预览图的 SVG 标注层中实现贝塞尔路径编辑器。框选精修和 PNG 二次编辑只维护各自的路径集合，所有指针交互、路径渲染、校验和序列化均复用同一组件与纯函数模块。

优点是能够沿用当前 React 和 SVG 架构、没有新增大型运行时依赖、路径坐标可直接归一化，并且容易通过纯函数测试验证。

### 未采用：引入完整画布库

Fabric.js 或 Konva 能提供成熟的节点拖拽能力，但会引入第二套场景树、坐标变换和事件系统。当前工作台已经有自己的缩放、框选和结果预览逻辑，引入大型画布库会显著扩大迁移面和回归风险。

### 未采用：简化多边形钢笔

只支持直线锚点更容易实现，但无法精确拟合圆角按钮和复杂轮廓，不满足完整 Photoshop 式钢笔的确认需求。

## 统一路径数据模型

每条标注保存为一个闭合路径对象：

```js
{
  id: "annotation-id",
  kind: "foreground" | "background" | "boundary",
  shape: "bezier_path",
  closed: true,
  anchors: [
    {
      x: 0.25,
      y: 0.40,
      in: { x: 0.22, y: 0.40 },
      out: { x: 0.28, y: 0.40 },
      handlesLinked: true
    }
  ],
  order: 0
}
```

锚点以当前编辑 PNG 或框选区域的宽高归一化到 `0..1`。`in` 和 `out` 是同一归一化坐标系中的绝对坐标，不是相对偏移；为保留画布边缘的平滑切线，手柄可越出 `0..1`。直线锚点的两个手柄与锚点重合。最终扁平化像素采样必须裁在源画布内。

路径原始锚点和手柄保留在前端任务元数据中，用于再次编辑。提交给执行器时额外生成确定性的扁平化轮廓点，采样误差不超过一个源图像像素，使现有遮罩处理不需要理解交互手柄。

标注优先级保持不变：后创建路径覆盖更早的保留或排除路径，边界路径维持最高边缘覆盖优先级。

## 钢笔交互

### 创建路径

- 单击空白位置创建直线锚点。
- 在创建锚点时拖拽，生成方向相反、长度对称的曲线手柄。
- 指针移动时显示从最后锚点到当前指针位置的预览曲线。
- 点击第一个锚点闭合路径。首点使用明显的闭合提示环。
- 路径至少需要三个不同锚点；不足三个锚点不能闭合。
- `Escape` 取消当前未闭合路径，不保存半成品。
- 切换工具、切换节点或退出编辑时，未闭合路径被取消，不自动猜测闭合。

### 编辑路径

- 点击路径或锚点进入路径编辑状态。
- 拖拽锚点移动锚点及其两个手柄。
- 拖拽手柄调整曲率。
- 默认手柄联动并保持共线；按住 `Option/Alt` 拖拽时只调整当前一侧手柄并解除联动。
- 双击锚点在直线角点与平滑锚点之间切换。
- 选中锚点后按 `Delete` 或 `Backspace` 删除；删除后少于三个锚点则删除整条路径。
- `Command/Ctrl+Z` 撤销最近一次创建或编辑动作。
- 点击路径外部退出选中状态，但保留路径。

### 外观与状态

- 所有闭合路径使用虚线外圈和半透明内部颜色。
- 保留路径使用绿色，排除或擦除路径使用橙红色，边界路径使用紫色。
- 选中路径提高虚线对比度，并显示锚点、手柄和控制线。
- 未选中路径只显示虚线边界和半透明填充，避免画面过于拥挤。
- 未闭合草稿只显示实线预览和锚点，不填充内部区域。
- 原“画笔大小”控件全部移除。
- 工具名称统一为“保留钢笔”“排除钢笔／擦除钢笔”“边界钢笔”。

## 共用组件边界

新增独立的路径模型和编辑器模块：

- 路径模型纯函数：创建锚点、更新手柄、闭合、删除锚点、坐标归一化、贝塞尔采样和有效性校验。
- SVG 编辑器组件：处理指针和键盘事件，渲染路径、锚点、手柄及草稿。
- 语义适配层：将统一路径模型映射为框选精修或 PNG 二次编辑的任务字段。

框选精修和 PNG 二次编辑分别拥有自己的路径状态、撤销历史和选中状态。它们不共享具体路径实例，只共享实现。

## PNG 二次编辑界面

PNG 结果进入编辑状态后显示：

- 最近一次成功透明 PNG，始终作为本次编辑底图。
- 三种钢笔工具。
- 独立的“二次编辑要求”多行输入框，内容不复用原始图层的拆分要求。
- 撤销、删除选中、清空路径、取消编辑和“发送调整”操作。
- 当前基准 PNG 版本和新任务状态。

只要存在非空二次编辑文字或至少一条有效闭合路径，“发送调整”即可使用。未闭合草稿不计入有效路径；若同时存在未闭合草稿，发送前提示用户先闭合或取消草稿。

提交成功后清空当前草稿，但保留已发送路径与文字的只读快照，便于查看本次任务使用了什么输入。

## PNG 结果版本状态

每个图层分别维护：

- `baseResult`：最近一次成功完成、当前可见并可编辑的 PNG。
- `pendingRevision`：正在排队或执行的二次编辑任务。
- `failedRevision`：最近一次失败任务及错误信息。
- `resultHistory`：所有成功 PNG 版本，按完成时间排序。

创建 `pendingRevision` 不会替换 `baseResult`。任务成功并且返回有效透明 PNG 后，才把新结果追加到历史并原子切换为新的 `baseResult`。任务失败或取消时继续显示原 `baseResult`，并允许以相同输入重试。

这会替换当前“同一节点最新任务直接覆盖显示结果”的逻辑，避免空任务或失败任务让原 PNG 消失。

## 二次编辑提交协议

二次编辑任务使用明确的 `task: "refine_split_result"` 和 `execution_route_hint: "result_refinement"`。提交内容包括：

- 当前 `baseResult` PNG 的嵌入数据或本地附件路径。
- PNG 解码后的实际像素宽高，作为 `source.canvas` 和标注坐标空间。
- 无限画布逻辑宽高与位置，放入独立的 placement 元数据，不参与图像处理尺寸校验。
- 独立的二次编辑文字要求。
- 闭合贝塞尔路径的原始锚点数据和扁平化轮廓点。
- 原 PNG 透明通道保持策略、结果版本 ID 和父版本 ID。

若只有文字，则执行器以完整 PNG 为可编辑输入；若有路径，则把路径范围作为允许修改区域。路径外像素和透明通道必须锁定。除非文字明确要求改变画布，否则输出保持输入 PNG 的实际像素尺寸。

预检器正式支持 `result_refinement` 路线，并校验：输入 PNG 可读、尺寸与声明一致、至少存在文字或有效闭合路径、所有路径坐标有限且位于画布内、父版本仍然存在。

## 执行与结果处理

工作台发送的 Codex 任务必须明确附带当前 `baseResult` PNG，而不是最初上传的整张设计稿。执行器只处理这一张 PNG 和本次二次编辑要求。

最终处理器校验输出尺寸、PNG 格式和透明通道。成功结果写入新版本文件，不覆盖父 PNG 文件。只有执行报告写为 `completed` 后，前端才切换结果；失败报告不得改变当前可见版本。

## 错误处理

- 路径未闭合：不发送，聚焦未闭合路径并给出明确提示。
- 路径坐标无效：阻止提交，不尝试静默修正。
- PNG 无法读取或实际尺寸不可获得：保留原结果并提示重新加载。
- 父版本文件缺失：任务预检失败，不回退到原始整图。
- 执行失败、取消或返回无效 PNG：保留原结果，显示失败原因并提供重试。
- 新任务排队：原 PNG 继续显示，同一图层的“发送调整”按钮禁用并明确显示当前排队任务，避免重复提交。

## 可访问性与快捷键

- 所有钢笔按钮保留 `aria-pressed` 和完整可读名称。
- 锚点、手柄和路径选中状态不仅依赖颜色，还通过形状和描边区别。
- 键盘焦点保持在编辑画布时才能捕获删除、撤销和取消快捷键，避免影响页面其他输入框。
- 文字输入框聚焦时不触发钢笔快捷键。

## 测试策略

采用测试先行方式实现：

1. 路径模型单元测试：直线锚点、曲线手柄、联动与解除联动、闭合条件、删除锚点、归一化和确定性采样。
2. 编辑器交互测试：创建、拖拽手柄、点击首点闭合、取消草稿、选择和删除、两套编辑器复用。
3. 提交协议测试：文字单独发送、路径单独发送、两者共同发送、未闭合禁止发送、实际 PNG 尺寸与逻辑 placement 分离。
4. 结果状态测试：排队和失败期间保留旧 PNG，新任务成功后才切换，历史版本不被覆盖。
5. 预检与执行路线测试：`result_refinement` 接受有效任务并拒绝缺失 PNG、无输入要求或非法路径。
6. 回归测试：原有框选、画布缩放、隐藏标注、任务确认和 PNG 下载保持正常。
7. 浏览器人工验证：圆角按钮、复杂轮廓、多路径重叠、高清透明 PNG 二次编辑和失败重试。

## 验收标准

- 工作台不再出现任何自由画笔入口或画笔大小控件。
- 两套编辑器都能创建和修改完整贝塞尔闭合路径。
- 闭合路径外圈为虚线，内部为对应语义的半透明颜色。
- 未闭合路径和少于三个锚点的路径不能发送。
- PNG 二次编辑区具有独立文字要求输入框。
- 文字或闭合路径任意一种都能提交二次编辑。
- 发送任务使用当前成功 PNG 及其实际像素尺寸，而不是原始设计图或逻辑显示尺寸。
- 排队、失败和取消不会让当前 PNG 消失。
- 新 PNG 只有在处理完成并通过格式、尺寸和透明通道校验后才替换当前版本。
