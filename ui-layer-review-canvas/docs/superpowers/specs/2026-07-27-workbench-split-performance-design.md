# 工作台拆分性能优化设计

## 目标

在不接入外部模型 API、不增加额外 Codex 会话往返的前提下，缩短从点击“拆分”到 PNG 回流的等待时间，并允许用户在处理期间继续操作其他节点。

成功标准：

- 点击“拆分”后 150ms 内进入明确的处理中状态。
- 提示词理解与拆分执行合并在同一个 Codex turn 内。
- 快速模式不生成备选方案，不执行全图分析，不进行自动重试。
- 快速模式仅在明确需要去字、补洞或补全遮挡时调用生成式修复。
- 使用固定基准图集记录各阶段耗时；简单原像素提取任务的中位耗时相对当前基线降低至少 40%。
- 任务运行期间可以切换、框选和编辑其他节点。

## 已确认的产品决策

不增加独立的“AI 优化”任务。用户可以填写口语化、简短或空白的拆分需求。当前拆分 Skill 在同一次执行内先规范化意图，再继续拆分。只有当选区所有权存在高风险歧义时才请求一次确认。

## 执行架构

### 1. 工作台即时准备

工作台在本地完成不需要模型的结构化工作：

- 根据节点类别补入保留、排除、修复和输出默认规则。
- 合并具体拆分需求、精修提示词、框选范围、画笔标注、去背景设置和执行模式。
- 在提交前生成精确框选预览图和掩码数据。
- 立即创建本地任务状态，不等待 Codex 完成后才释放界面。

这些规则只补全缺失约束，不改写用户明确输入。

### 2. 单次 Codex turn

一次拆分只创建一个 Codex turn。turn 内部顺序为：

1. 将口语化需求规范成简短的结构化执行要求。
2. 根据任务特征选择最短执行路线。
3. 执行拆分和必要的局部修复。
4. 验证尺寸、透明通道和明显排除项。
5. 回传 PNG 和阶段耗时。

规范化结果写入执行报告，不单独回写会话，也不要求普通任务二次确认。

### 3. 最短路线选择

快速模式采用以下优先级：

1. **直接裁切**：无需去背景、无需文字移除、无需补全时直接输出框选像素。
2. **裁切加透明化**：只需要主体隔离时生成一次主体掩码并合成透明 PNG。
3. **局部修复**：仅当需求明确包含去字、补洞或遮挡补全时，对批准区域执行一次修复。

快速模式禁止：

- 全页面重新诊断。
- 创建额外图层或候选图。
- 对完整选区进行重绘。
- 失败后自动切换到高质量流程。
- 未经需要调用生成式修复。

高质量模式保留完整边缘复检和最多一次局部重试，但不能改变输出尺寸、位置和透明 PNG 合同。

## 复杂 UI 处理

复杂不等于自动走慢路径。先判断当前任务需要的是提取、透明化还是局部修复。

仅在以下情况返回“需要确认”：

- 框选内包含多个独立组件，且需求无法判断目标所有权。
- 保留和排除标注发生无法按顺序解析的冲突。
- 要求同时声明保留与删除同一关键结构。

其他情况使用类别默认规则继续执行。高风险确认只提出一个具体问题，并保留当前任务状态。

## 异步交互

- 提交成功后，当前节点立即显示阶段状态和真实已耗时。
- 用户可以切换到其他节点继续框选或编辑。
- 同一节点在运行时禁止重复提交；其他节点不受影响。
- 任务完成、失败或需要确认时更新左侧节点状态。
- 页面刷新后从任务记录恢复状态，不把已完成或失败任务显示为处理中。

## 性能记录

每个任务记录以下时间点：

- `submitted_at`
- `codex_turn_started_at`
- `intent_normalized_at`
- `extraction_started_at`
- `repair_started_at`（未使用时为空）
- `validation_started_at`
- `completed_at`

执行报告同时记录实际路线：`direct_crop`、`alpha_extract` 或 `targeted_repair`。工作台只显示简化进度，详细耗时保留用于诊断。

## 错误处理

- Codex turn 未启动：任务立即失败并允许重新提交。
- 快速模式验证失败：返回失败原因，不自动升级高质量模式。
- 高风险歧义：任务进入 `needs_confirmation`，不继续计入处理中。
- PNG 已回流但 turn 未正确收尾：以文件验证结果和 turn 终态共同结束任务，避免永久处理中。

## 验证

建立包含以下场景的固定基准：

1. 纯裁切组件。
2. 去背景的单一图标。
3. 去文字并补全底板。
4. 被遮挡组件的局部补全。
5. 框内含多个独立组件的歧义任务。

每个场景验证输出尺寸、真实 alpha、坐标稳定性、排除项和阶段耗时。性能优化以同一设备、同一输入、同一模式的前后中位耗时比较，不以单次最快结果判断。
