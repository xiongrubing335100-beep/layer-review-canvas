# Imvia Layer 工作台使用规范

## 1. 文档目的

本规范面向 Imvia Layer 工作台的实际使用者，覆盖从打开工作台、上传原图、检查自动识别结果、框选拆分、钢笔精修、填写提示词、发送任务、查看队列、验收 PNG，到 PNG 二次编辑和下载导出的完整流程。

使用工作台时遵循三条总原则：

1. 框选负责确定图层的逻辑范围与位置。
2. 钢笔路径负责说明“在哪里、允许做什么”。
3. 提示词负责说明“目标应当变成什么样”。

尺寸、坐标映射、透明通道、路径外像素锁定和标准画布由系统处理，用户不需要把这些技术要求写进提示词。

## 2. 打开工作台

在 Codex Desktop 当前任务中发送：

```text
[@imvia-layer](plugin://imvia-layer@personal) 打开工作台
```

工作台会在当前任务的右侧浏览器打开。正常使用时不需要手动启动开发服务，也不需要直接输入 `127.0.0.1` 地址。

打开后先检查顶部会话状态：

- 绿色圆点和“已就绪”：工作台已连接当前 Codex 任务，可以发送拆分请求。
- “检测中”：等待连接检测完成。
- “未连接”：不要发送任务；重新打开工作台或检查本地插件状态。

工作台发送的拆分任务会作为可见消息进入当前 Codex 任务，不会静默转为不可见的后台任务。

## 3. 工作台区域说明

### 3.1 顶部栏

顶部栏用于查看当前会话连接、已确认数量、切换工作模式和导出结果。

- “框选拆分”：逐项检查和编辑拆分区域。
- “画布总览”：查看原图节点、拆分节点和当前成功结果。
- “发送已确认”：批量发送已经确认且尚未产出当前版本的拆分项。
- “下载与导出”：下载全部成功 PNG 或导出拆分计划 JSON。

### 3.2 左侧拆分栏目

左侧栏展示：

- 当前原始画布及实际像素尺寸。
- 自动识别或手工建立的拆分项。
- 每个拆分项所属类别、缩略图、范围比例和处理状态。

拆分项可能显示以下状态：

- “待确认”：需要检查框选和要求。
- “已确认”：可以发送。
- “需补全”：预计需要生成式补全或边缘修复。
- “处理中”或“排队中”：任务已经发送，不能重复提交。
- “结果已产出”：存在成功 PNG。
- “失败”：本次任务未成功，当前旧结果仍应保留。

### 3.3 中央预览区

中央区域用于对照：

- 原图中的逻辑位置。
- 当前框选区域的大图预览。
- 钢笔路径、锚点和控制柄。
- Codex 返回的当前成功结果。

放大预览必须按原图宽高比等比例显示，不得横向压缩或纵向拉伸。预览缩放只影响显示，不改变实际输出像素和逻辑位置。

### 3.4 右侧设置区

右侧区域用于编辑当前拆分项：

- 图层名称。
- 具体拆分需求。
- 快速要求标签。
- 快速或高质量模式。
- 是否去除背景。
- 钢笔边界精修。
- 确认、拆分、重新拆分和任务状态。

## 4. 完整操作流程

### 第一步：上传原图

支持常见 PNG、JPG、JPEG 和 WebP 图片。上传后工作台读取图片实际像素尺寸，并进行本地快速识别。

重新载入原图会建立新的原图上下文。不要把不同设计稿误认为同一张图的版本；多张原图应各自拥有独立的拆分项、任务和结果。

### 第二步：检查自动识别结果

自动识别完成后，逐项检查：

- 图层类别是否正确。
- 图层名称是否能准确识别目标。
- 框选是否完整覆盖对象、阴影、描边和需要补出的遮挡区域。
- 是否误包含无关文字、背景或邻近对象。
- 是否需要去背景。
- 是否需要钢笔精修。

自动识别结果只是候选，不应未经检查直接批量发送。

### 第三步：调整框选

框选定义图层在原图中的逻辑范围和无限画布中的位置。

- 框选应包含目标主体的全部可见像素。
- 需要补全被遮挡部分时，应为补全结构预留合理空间。
- 阴影、光晕、描边和附着装饰需要保留时必须纳入框选。
- 不要为了保险框住整张图；范围越大，错误包含和重新构图风险越高。
- 修改框选后，已产出的旧版本不会自动改变；需要重新拆分才生成新版本。

### 第四步：选择类别并填写拆分要求

确认当前拆分项属于正确类别，然后按照本规范第 8 节填写“具体拆分需求”。

快速要求标签只能作为补充，不应替代完整、明确的主要要求。

### 第五步：选择拆分模式

#### 快速

- 优先提取原图可见像素。
- 只在必要时进行一次局部补全。
- 适合边界清晰、遮挡少、要求明确的对象。

#### 高质量

- 允许更完整的补全与边缘复检。
- 首个结果失败时可进行一次定向重试。
- 适合遮挡严重、结构复杂、阴影或半透明边缘较多的对象。

高质量不表示允许重新设计；无论模式如何，都必须保留未批准区域和原始视觉关系。

### 第六步：决定是否去除背景

开启“去除背景”表示最终需要真实透明 RGBA PNG。

- 独立 KV 元素、UI 组件和需要复用的前景素材通常开启。
- KV 背景通常关闭，除非明确要求透明背景图层。
- 文字和 Logo 应优先使用原像素锁定的透明流程，避免模型重绘字形。
- PNG 二次编辑不得再次调用 RMBG；其 Alpha 由基准 PNG 和结构化路径继承或修改。

### 第七步：按需使用钢笔

仅在框选矩形无法准确表达保留、排除或修复边界时使用钢笔。详细规则见第 7 节。

### 第八步：确认拆分项

检查无误后点击“确认并下一个”。确认表示当前框选、图层名称、拆分要求、模式、去背景设置和钢笔标注共同构成权威计划。

如果随后修改任一内容，状态应回到待确认，需要再次确认。

### 第九步：发送任务

可以发送当前拆分项，也可以点击“发送已确认”批量发送。

- 同一拆分项已有任务排队或执行时，不要重复发送。
- 当前 Codex 任务繁忙时，新任务会进入工作台队列。
- 排队中的任务只有在前一个任务终止后才进入当前会话执行。
- 取消排队任务只取消尚未进入执行的任务，不应删除原图或旧成功结果。

### 第十步：验收结果

成功结果返回后检查：

- 对象数量和身份正确。
- 尺寸、比例和结构没有变形。
- 必须保留的像素、文字、Logo、阴影和光效仍然存在。
- 应删除的内容已经消失。
- 被遮挡区域补全合理，没有新增无关元素。
- 透明 PNG 没有白底、黑底或画进像素的棋盘格。
- 边缘没有明显黑边、白边、过度虚化或锯齿。

不合格时不要把错误结果当作新的基准 PNG。应修改框选、路径或要求后重新拆分。

## 5. 拆分类别使用规范

### 5.1 KV 标题

用于主标题、活动标题、核心文字 Logo 或标题附着光效。

重点：

- 保留原文字内容、字形、描边、材质、排列和附着光效。
- 原图可见像素必须锁定。
- 只补全被遮挡或裁切的缺失部分。
- 不得改字、重新排版或把标题重绘成近似字体。

### 5.2 KV 元素

用于轮盘、商品、人物、IP 角色、装饰主体、奖品或其他主视觉前景。

重点：

- 保留主体可见像素、阴影和附着装饰。
- 只补全被其他元素遮挡的部分。
- 不得改变主体身份、比例、姿态或材质。
- 多个可独立复用的对象应拆成多个拆分项。

### 5.3 普通文字

用于页面内非主标题的说明文字、标签、数字和 UI 文案。

重点：

- 同一业务区域的普通文字可合并为一个透明图层。
- 保持原始坐标、字号、颜色、抗锯齿和行距。
- 不得把文字与底板合并，除非明确要求整体组件。

### 5.4 UI 组件

用于按钮、卡片、面板、输入框、标签底板和其他界面组件。

重点：

- 输出干净组件底板。
- 按要求移除普通文字或可替换内容。
- 补全文字挖空和遮挡形成的缺口。
- 保留边框、圆角、渐变、阴影和光效。

### 5.5 KV 背景

用于移除前景和标题后的完整背景层。

重点：

- 移除标题、KV 前景元素和不属于背景的 UI 内容。
- 只修复遮挡产生的洞。
- 未遮挡背景区域保持原图，不得整体重绘。
- 背景结果应位于 UI 组件栏目之后，作为最后一类处理。

## 6. 框选使用规则

### 6.1 正确框选

- 框选边缘与目标之间保留少量安全距离。
- 需要真实阴影时把完整阴影纳入范围。
- 需要补全裁切对象时把预期补全空间纳入范围。
- 框选尺寸是逻辑尺寸和定位依据，不等同于 ImageGen 原生生成尺寸。

### 6.2 常见错误

- 框选太紧：阴影、描边或缺失补全空间被切掉。
- 框选太大：包含邻近对象，模型难以判断主体。
- 一个框选包含多个应独立复用的对象。
- 只在提示词中说“旁边不要”，但框选仍包含大量无关内容。
- 把放大预览的显示尺寸误认为最终 PNG 像素尺寸。

## 7. 钢笔工具使用规范

### 7.1 共通操作

- 点击添加直线锚点。
- 点击并拖动建立曲线手柄。
- 点击第一个锚点闭合路径。
- 路径至少包含三个不同锚点。
- `Option/Alt` 拖动可解除单侧手柄联动。
- 双击锚点在角点与平滑点之间切换。
- 选中锚点后按 `Delete` 或 `Backspace` 删除。
- `Command/Ctrl+Z` 撤销，`Command/Ctrl+Shift+Z` 或 `Ctrl+Y` 重做。
- `Escape` 取消尚未闭合的草稿。
- 切换工具、切换拆分项或退出编辑时，未闭合草稿应被取消。

闭合路径使用动态虚线外圈和语义半透明填充；锚点使用清晰绿色正圆。编辑画面中的指针应显示钢笔图标，不使用容易误解为框选或移动的十字图标。

### 7.2 边界钢笔：限定局部修复范围

适用于补全残缺对象、修复边缘、替换小范围内容或调整局部材质。

- 路径内部是允许生成式修改的区域。
- 路径外部保持原图或基准 PNG 像素不变。
- 它不表示“删除路径外内容”。
- 路径应紧贴目标，并包含需要补出的缺失区域。
- 一个独立对象使用一条独立路径。

示例：修复两个残缺金币时，分别为两个金币画两条路径，不要把整个轮盘和人物一起框住。

### 7.3 排除钢笔：删除内容

适用于排除多余物体、背景残留、脏边、文字或装饰。

- 首次拆分时，路径内部被标记为必须排除。
- PNG 二次编辑时，路径内部 Alpha 确定性设置为零。
- 单纯删除不应依赖 ImageGen 理解“去掉”。
- 如果删除后需要补背景，使用另一条边界路径标出需要生成式补全的范围。

### 7.4 保留钢笔：保护原始像素

适用于人物脸部、Logo、文字、产品主体或其他绝对不能变化的内容。

- 路径内部必须保留原始 RGBA 像素。
- 与修复或排除路径重叠时，保留路径拥有最高优先级。
- 保留钢笔不是复制工具，也不会自动删除路径外内容。

### 7.5 “仅保留路径内，路径外透明”

这是显式画布操作，不是边界钢笔的默认含义。

正确流程：

1. 用边界钢笔画出需要保留的完整主体轮廓。
2. 开启“仅保留路径内，路径外透明”。
3. 如需修复主体内部残缺，再为每个残缺对象添加独立边界路径。
4. 提示词只描述修复目标，不再重复“框外删除”。

没有开启该操作时，路径外像素必须保持原样。

### 7.6 路径绘制标准

- 路径必须闭合，不能自相交。
- 所有锚点必须位于图像像素画布内。
- 普通边缘修复在目标外保留约目标尺寸的 3%–8%。
- 阴影、光晕或半透明边缘可扩大到 8%–15%。
- 不要把路径贴死在残缺断面上。
- 不要为了保险框住整张画面。
- 单条局部修复路径覆盖画布超过 40% 时应检查是否过大。
- 覆盖超过 70% 时默认不能发送，除非明确选择高风险“整图编辑”。

## 8. 首次拆分提示词规范

首次拆分的“具体拆分需求”推荐使用以下结构：

> 输出对象 + 必须保留 + 必须移除 + 需要补全 + 禁止变化

### 8.1 通用模板

```text
单独输出【目标对象】。
保留【可见像素、描边、材质、阴影或光效】。
移除【文字、背景或遮挡对象】。
仅补全【被遮挡或裁切的部分】。
不得改变【对象身份、比例、位置或未遮挡区域】。
```

### 8.2 KV 标题示例

```text
单独拆出 KV 主标题，保留原文字内容、字形、描边、材质和附着光效。
锁定原图可见像素，只补全被遮挡的缺失笔画。
不得改字、重新排版或改变标题比例。
```

### 8.3 KV 元素示例

```text
单独拆出已框选的抽奖轮盘主体，保留原图可见像素、描边、材质和阴影。
移除叠加文字与无关前景，只补全被遮挡的轮盘结构。
不得移动、缩放或重新设计轮盘。
```

### 8.4 UI 组件示例

```text
输出干净的按钮底板，移除按钮文字。
补全文字遮挡形成的渐变、描边和高光，保留原圆角、阴影和尺寸比例。
不得新增文字或改变按钮形状。
```

### 8.5 KV 背景示例

```text
输出完整 KV 背景，移除标题、人物和前景装饰。
只补全遮挡形成的空洞，延续周围背景纹理和光影。
未遮挡背景区域必须保持原图，不得整体重绘。
```

## 9. 提示词书写通用规则

### 9.1 推荐结构

无论首次拆分还是二次编辑，都按以下顺序表达：

> 修改对象 + 修改动作 + 目标状态 + 必须保持 + 禁止变化

### 9.2 应该写

- 明确对象身份，例如“左侧红包”“右下角金币”“已标注按钮底板”。
- 使用明确动作，例如“补全”“移除”“修复缺口”“延续渐变”。
- 说明必须保持的视觉属性。
- 说明禁止变化的邻近结构。
- 一次任务只表达一种主要视觉意图。

### 9.3 不需要写

- 标准画布尺寸。
- `content_region` 坐标。
- RGBA、Alpha、RMBG 等执行参数。
- “输出路径”和本地文件名。
- 路径外像素锁定等系统自动约束。

### 9.4 避免使用

- “这里”“那里”“旁边”“差不多”等模糊指代。
- “好看一点”“高级一点”等没有可验收标准的描述。
- 同时要求“整体变化”和“所有内容完全不变”。
- 用提示词代替排除、保留或仅保留路径内操作。

## 10. PNG 二次编辑规范

### 10.1 基准版本

- 当前最近一次成功 PNG 是唯一权威基准。
- 新任务排队、失败或取消时继续显示基准 PNG。
- 只有新 PNG 完成并通过尺寸、Alpha 和结构验收后才切换。
- 不要使用最初上传的整图代替当前成功 PNG 进行二次编辑。

### 10.2 局部编辑流程

1. 打开当前成功 PNG 的“编辑结果”。
2. 为每个需要修复的对象分别画闭合边界路径。
3. 删除使用排除路径，保护使用保留路径。
4. 在独立“修改目标”输入框填写简短要求。
5. 检查系统生成的结构化摘要。
6. 点击“发送调整”。

原 PNG 或局部 ROI 必须按 1:1 放入标准画布，禁止非等比缩放。ImageGen 只处理每条闭合路径对应的独立局部 ROI，最终按原像素坐标合成；路径外 RGBA 像素逐字节保持不变。

普通局部二次编辑必须至少有一条有效闭合路径。只填写文字不能隐式获得整张 PNG 的修改权限；如确实需要修改全图，必须明确开启高风险“整图编辑”并再次确认。

### 10.3 二次编辑提示词模板

```text
仅处理已标注的【对象】。
将其【修改动作】，达到【目标状态】。
保持原有【位置、大小、角度、材质、光影】。
不得修改【其他对象或结构】。
```

系统自动补充局部 ROI、路径外锁定、尺寸和透明约束。

### 10.4 局部补全示例

```text
补全已标注的两个残缺金币，使其成为结构完整的圆形金币。
保持金币原位置、大小、角度、材质和光影。
不要移动或重绘轮盘、人物及其他金币。
```

两个金币必须分别使用两条闭合边界路径。

### 10.5 删除并补背景示例

```text
删除排除路径内的装饰物。
在边界路径内补全其后方原有背景纹理和光影。
保持周围主体、颜色和透视关系不变。
```

### 10.6 边缘修复示例

```text
修复已标注主体的缺口和锯齿边缘。
延续现有轮廓、描边、材质和光影，不改变主体形状与比例。
```

### 10.7 文字或 Logo 修复示例

```text
仅修复已标注文字的缺失笔画，保持原文字内容、字形、描边和排列。
不得改字、重新排版或改变文字比例。
```

文字和 Logo 的 RGB 应优先锁定原图，不应让 ImageGen 重绘最终字形。

## 11. 错误提示词及改写

### 11.1 指代不清

不推荐：

```text
把这里修一下，旁边两个也补好。
```

推荐：先分别给目标画路径，再写：

```text
补全两个已标注金币的缺失部分，保持各自原位置、大小和透视。
```

### 11.2 把路径语义写进提示词

不推荐：

```text
保留框内，框外全部删除，然后修复里面的东西。
```

推荐：开启“仅保留路径内”，再写：

```text
补全已标注金币的缺失结构，保持其材质和光影。
```

### 11.3 要求互相冲突

不推荐：

```text
整体更饱满，但所有元素位置和比例完全不变。
```

推荐：

```text
仅增强已标注金币表面的高光和立体感，不改变轮廓、位置和大小。
```

### 11.4 一条路径承担多个任务

不推荐：用一条覆盖整张 PNG 的路径，同时要求删除背景、修复金币、移动人物和调整轮盘。

推荐：删除使用排除路径，局部补全使用边界路径，保护对象使用保留路径；复杂目标拆成多次任务。

## 12. 任务、队列和结果版本

### 12.1 任务状态

- 尚未发送：仍可自由修改。
- 待接收或排队：等待当前 Codex 任务空闲。
- 执行中：已经进入当前会话处理。
- 完成：结果已通过最终验收。
- 失败或取消：不会替换当前成功结果。

### 12.2 排队规则

- 同一 Codex 会话同时只执行当前前台任务。
- 后续任务在工作台显示排队，不应在会话中重复出现空白任务消息。
- 前一个任务完成、失败或取消后，队列才发送下一条可见任务消息。
- 用户取消尚未发送的排队任务后，不得再次自动发送。

### 12.3 版本规则

- 每次成功结果写入新版本，不覆盖父 PNG。
- 画布只展示当前成功版本节点。
- 历史成功文件和任务记录继续保留。
- 二次编辑始终从当前成功版本开始。

## 13. 下载与导出

- 单个结果使用结果区域的“下载 PNG”。
- 顶部“下载全部 PNG”只包含已经成功产出的结果。
- “下载拆分计划”导出当前已确认的 JSON 计划，不等同于图片文件。
- 下载前确认 PNG 尺寸、透明背景和图层名称正确。

## 14. 常见问题处理

### 14.1 画面拉伸或压缩

- 检查是否误用整图编辑或超大路径。
- 确认预览使用等比例显示。
- PNG 二次编辑应使用 1:1 标准画布与局部 ROI，不允许强制缩放候选。
- 出现比例漂移的候选必须失败，不能通过缩放修正后交付。

### 14.2 透明结果出现黑边、白边或虚化

- 检查原素材是否本身带阴影或半透明边缘。
- 确认没有把可见棋盘格当成透明背景。
- 文字和 Logo 不应使用普通 RMBG 重绘流程。
- PNG 二次编辑的 Alpha 应由基准 PNG 和显式路径控制。

### 14.3 提示词没有被正确理解

- 检查是否使用了模糊指代。
- 检查对象是否分别使用独立路径。
- 检查“删除”“保留”“路径外透明”是否使用了正确的结构化操作。
- 把复杂目标拆成多个独立任务。
- 只写视觉目标，不要同时写技术执行流程。

### 14.4 新任务失败后原 PNG 消失

这是不允许的状态。失败、排队和取消期间必须继续展示当前成功 PNG；只有新版本成功后才能原子切换。

### 14.5 会话繁忙但工作台显示排队

等待当前任务结束。排队只表示任务已经被工作台记录，不表示会话中已经出现第二条执行消息。

## 15. 首次拆分提交前检查

- 原图和实际像素尺寸正确。
- 拆分类别和名称正确。
- 框选完整且没有包含无关对象。
- 阴影、光效和需要补全的空间已纳入框选。
- 具体拆分需求包含保留、移除、补全和禁止变化。
- 快速或高质量模式选择合理。
- 去背景开关符合最终用途。
- 所有钢笔路径已闭合。
- 已逐项确认。
- 没有重复发送正在执行的拆分项。

## 16. PNG 二次编辑提交前检查

- 当前显示的是希望继续编辑的成功 PNG。
- 每个待修复对象都有独立闭合路径。
- 缺失部分位于边界路径覆盖范围内。
- 删除区域使用排除钢笔。
- 必须保护的内容使用保留钢笔。
- “仅保留框内”通过显式操作开启，而不是只写在提示词中。
- 修改目标没有使用“这里、那里、旁边”等模糊指代。
- 没有无意中选择整图编辑。
- 系统摘要与自己的真实意图一致。

## 17. 工作台自动承担的责任

工作台必须自动完成，且不得要求用户写进提示词：

- 读取原图或当前成功 PNG 的实际像素尺寸。
- 将逻辑尺寸、输出尺寸和 ImageGen 标准画布严格分离。
- 预览图始终等比例显示。
- PNG 二次编辑按 1:1 放入标准画布。
- 将每条修复路径转换为独立局部 ROI。
- 锁定未批准区域的 RGBA 像素。
- 自动编译用户文字、路径语义、保持项和禁止项。
- 确定性执行排除、保护和仅保留路径内的 Alpha 操作。
- 验证格式、尺寸、比例、透明通道和路径符合性。
- 失败、排队和取消时保留当前成功版本。
- 只有最终处理成功后才切换版本并提供下载。
